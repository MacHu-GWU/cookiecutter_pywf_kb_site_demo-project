# Spec: plan.md 写作计划

> 管辖范围: 一篇文档的 `plan.md` 写什么, 怎么写. 它在文档目录根下, 和 `README.md` 并列, 不进网站. 素材的格式见 [05-resources.md](05-resources.md).

---

## 1. 它是干什么的

`plan.md` 是作者动笔之前 (和动笔过程中) 的想法落盘: 这篇想说什么, 当时的背景是什么, 按什么顺序说, 每个点靠哪份素材撑着. 写正文的人 (作者或 AI) 读它就知道该写什么. 下一次回来改这篇的 agent 也读它.

它没有 frontmatter, 不受 [07-readme-body.md](07-readme-body.md) 的标题规则限制. 语言和标点按 [03-language-punctuation.md](03-language-punctuation.md).

---

## 2. 模板

模板在 `assets/plan-template.md`, 固定这几节, 顺序不变, 没想好的节留空:

| 节 | 写什么 |
| :--- | :--- |
| `## 种子` | 这篇是怎么来的: 做了什么事, 看了什么, 从哪迁过来. 一两句话 |
| `## 背景` | 现场: 当时在做什么项目, 遇到什么问题, 约束是什么 (时间, 成本, 团队, 技术栈), 考虑过哪些别的方案. 这是正文开头的原料, 尽量用作者原话 |
| `## 读者` | 主要写给谁: 未来的自己, agent, 还是要发给某个人看 |
| `## 核心观点` | 一句话说清这篇的结论. 说不成一句话, 说明还没想清楚 |
| `## 要讲的点` | 按顺序列出要讲的点, 大致就是正文的 H2. 每个点后面标它靠哪份素材 |
| `## 素材怎么用` | 一张表, 见第 3 节 |
| `## 没想清楚的` | 还在纠结的问题, 以及 AI 提了但作者还没点头的建议 |
| `## 随手记` | 作者说到哪记到哪, 还没归位的想法. 想清楚了就挪到对应的节, 从这里删掉 |

`## 背景` 是 kb 比 blog 多的一节. kb 文档最常见的毛病就是缺背景, 所以单独留一节逼着把它问出来.

---

## 3. 素材怎么用

每份用到的素材在表里占一行:

```markdown
| 素材 | 用法 | 用在哪 | 说明 |
| :--- | :--- | :--- | :--- |
| [confluence-<slug>.md](resources/confluence-<slug>.md) | 改写 | 全篇 | 作者的旧稿, 这篇从它改出来 |
| [<来源>-<内容>.md](resources/<来源>-<内容>.md) | 提到 | 第 3 点 | 用一句话转述它的结论, 给链接 |
| [<来源>-<内容>.md](resources/<来源>-<内容>.md) | 背景 | 无 | 只帮写的人理解机制 |
```

用法有四种:

- **改写**: 作者自己的旧稿, 这篇就是从它改出来的. 内容可以全部重组, 观点和事实不能丢.
- **引用**: 正文里直接放原文的一两句话, 注明出处.
- **提到**: 用自己的话转述或一句带过, 给链接.
- **背景**: 只帮写的人理解, 正文里不出现.

`resources/` 里没进这张表的素材, 就是还没决定怎么用.
