# Workflow: 写正文的过程

> 不管是从 plan 写, 把粗稿改成规范稿, 还是把 Confluence 旧稿改写成文章, 写正文都走这个过程. 写什么样的东西见 `02-spec/04-tone.md` 和 `02-spec/07-readme-body.md`, 本文只管怎么一步步写出来.

---

## 1. 先把背景问出来

kb 文档最常见的毛病是缺背景 (见 [../01-strategy/01-positioning.md](../01-strategy/01-positioning.md) 第 3 节). 动笔前确认 `plan.md` 的 `## 背景` 能回答这几个问题, 回答不了就问作者:

1. 当时在做什么项目或产品, 为什么需要做这件事?
2. 有什么约束 (时间, 成本, 团队, 已有的技术栈)?
3. 考虑过哪些别的方案, 为什么没选?
4. 实际做的时候踩了什么坑, 哪一步最花时间?
5. 现在回头看, 结论是什么? 什么情况下不该这么做?

规则:

- **一次最多问三到五个问题**, 用列表编号, 作者可以挑着答. 不要一次甩十个.
- **问的是作者的经历和判断, 不是技术事实.** 技术事实 (API 怎么用, 版本号) 自己查.
- **作者答了就马上记进 `plan.md`**, 用作者的原话, 告诉作者一行 "记进了 `背景`".
- **作者说不记得或不想说, 就不写.** 不要编一个听起来合理的背景, 也不要写 "笔者当时..." 这种假装的经历.

---

## 2. 先给提纲, 作者点头再写

列出 H1 和每个 H2 (需要时到 H3), 每个 H2 下面一句话说这节讲什么, 靠哪份素材. 标题写成直白的判断句, 只读标题就能串起全篇.

改稿或迁移时, 提纲里再标出: 哪几节来自原稿, 哪几节合并, 拆开, 新加, 原稿里哪些内容这次删掉以及为什么删.

作者点头才写全文. 作者改了提纲, 按作者的改.

---

## 3. 写

- **开头**: H1 下面一两段, 用 `背景` 交代问题和现场, 再说这篇的结论或读完能得到什么.
- **讲道理的 H2** 按 "三明治" 写: 大白话破题, 事实和机制, 一句话收住.
- **讲操作的 H2**: 先说这一步要达到什么目的, 为什么需要; 再给步骤和代码; 最后说怎么确认做对了, 以及常见的错. 官方文档里查得到的细节压缩成一两句, 给链接.
- **结尾**: 一节收住全篇: 结论, 适用边界, 已知的问题和下一步. 不写客套话.
- 事实, 数字, 经历只用 `plan.md`, `resources/` 和作者给的. 不编.
- 写的时候就用英文半角标点, 零感叹号.
- 写的过程中作者冒出新想法, 记进 `plan.md` 的 `随手记`.

---

## 4. 改稿时: 常见毛病和改法

AI 生成的笔记, runbook, 以及作者早期随手写的稿子, 通常有这些毛病:

| 毛病 | 改法 |
| :--- | :--- |
| 没有背景, 一上来就是步骤 | 用 `背景` 写开头, 问不出来就问作者 |
| "概述" 一节只是把目录念一遍 | 删掉, 换成真正的开头段 |
| 整段整段加粗, 每个列表项都加粗 | 去掉加粗, 只留真正要强调的一两个词, 警告改用 ```` ```{warning} ```` |
| ✅ ❌ ⚠️ 做的清单, "总结" 里重复一遍正文 | 删掉, 或者改成一张对比表 |
| 编出来的耗时和工作量, 没量过的数字 | 删掉, 除非作者确认是真的 |
| 每一步只有 "怎么做", 没有 "为什么" | 补一句为什么; 补不出来, 说明这一步不重要, 可以压缩 |
| 代码缺 import, 用了没定义的名字, 用了废弃的 API | 修好; 修不了就在代码前说明这是片段 |
| 同一件事给了好几种写法或平台, 而且都很长 | 保留作者实际用的那种, 其他用 `tab-set` 或者一句话带过 |
| 把所有可能的选项都列一遍, 作者其实只用了一个 | 讲作者用的那个, 其他的一句话说为什么没用 |
| 结尾的 "下一步" 清单和祝福语 | 换成真正的结尾: 结论和适用边界 |
| 版本号, 界面菜单名, 价格和限额可能已经过时 | 查官方文档核实; 核实不了, 写明 "以写作时 (YYYY-MM) 为准" |

**作者原有的观点, 真实经历, 数字和判断一律保留**, 只改结构, 标题和不合规的地方. 不要把作者的话改成你的话.

---

## 5. 收尾

1. 作者指定了自己的文风规范时, 对照它过一遍.
2. 改准 `description` (见 `02-spec/02-metadata.md`), 补 `tags`, 改了正文就把 `updated_at` 改成今天.
3. 中文文档跑 `c2ep`, 检查误伤 (见 `02-spec/03-language-punctuation.md`).
4. 逐项过 `02-spec/09-checklist.md`, 跑 `check` 和 `lint-doc`.
5. 告诉作者: 文档路径, 写了哪几节, 删了原稿的什么 (如果是改稿), 还有哪些点等作者补.
